# GS8 Triple 0.6.0 — проект Android

Приложение предназначено для размещения трёх Android-приложений в отдельных Freeform-окнах на GAC GS8 Gen2.

## Раскладка экрана 1920×968

- Слева у водителя: Музыка, x=0..400 (400 px).
- Центр: Навигатор, x=400..1160 (760 px).
- Справа: Rutube или выбранное приложение, x=1160..1920 (760 px).

## Сборка APK без Android Studio — через GitHub Actions

В архив уже добавлен workflow `.github/workflows/android-apk.yml`. Он автоматически собирает debug APK в облаке GitHub и прикладывает APK к запуску сборки.

### Что понадобится

- аккаунт GitHub;
- браузер;
- этот ZIP-архив.

### Первый запуск

1. Распакуй ZIP на компьютере. Внутри должна быть папка `GS8Triple`, а в ней `app`, `build.gradle.kts`, `settings.gradle.kts`, `README_RU.md` и скрытая папка `.github`.
2. На GitHub создай новый репозиторий, например `GS8Triple`. Для простоты можно выбрать **Private**. Не добавляй автоматически README, .gitignore или лицензию — они уже есть в проекте.
3. Открой пустой репозиторий и выбери **Add file → Upload files**. Перетащи в окно загрузки ВСЁ содержимое папки `GS8Triple`, включая скрытую папку `.github` и файл `.gitignore`. Важно: загружать содержимое папки проекта, а не ZIP как один файл.
4. Нажми **Commit changes**.
5. Открой вкладку **Actions**. Если GitHub спросит разрешение на запуск workflows, подтверди его.
6. В списке выбери **Build GS8 Triple APK** → **Run workflow** → **Run workflow**.
7. Дождись зелёной отметки успешной сборки. Открой завершённый запуск и внизу страницы скачай артефакт **GS8-Triple-debug-APK**.
8. Распакуй скачанный артефакт ZIP — внутри будет `app-debug.apk`.

При каждом последующем `Commit` в ветку `main` или `master` сборка также будет запускаться автоматически.

## Технические параметры сборки

- Android Gradle Plugin: 8.7.3
- Kotlin: 2.0.21
- Gradle: 8.9 (устанавливается workflow)
- JDK: 17 (устанавливается workflow)
- compileSdk: 35
- minSdk: 28 (Android 9)
- targetSdk: 28
- applicationId: `ru.gs8triple`
- Debug APK: `app/build/outputs/apk/debug/app-debug.apk`

Gradle Wrapper намеренно не добавлен: облачный workflow устанавливает Gradle 8.9 напрямую. Поэтому локальная Android Studio для облачной сборки не требуется.

## Что реализовано в коде 0.6.0

- Выбор приложений с Launcher Activity для каждого из трёх слотов.
- Сохранение выбранных пакетов.
- Shizuku API 13.1.5 и ShizukuProvider.
- Запрос Shizuku runtime permission.
- Shizuku UserService для выполнения команд управления окнами.
- Резервное выполнение через `su -c`, если Shizuku не подключён.
- Запуск выбранных Activities с `--windowingMode 5`.
- Поиск Task ID через `dumpsys activity activities` и попытка изменить границы через `am task resize`.
- Диагностика UID, Shizuku Binder, разрешения, Freeform flags и multi-window.

## Важные ограничения — не считать приложение проверенным

Архив содержит исходный проект и конфигурацию облачной сборки. Сам APK ещё не подтверждён успешной компиляцией и не проверен на магнитоле.

- Формат `dumpsys activity activities` у OEM-прошивки может отличаться; парсер Task ID может потребовать адаптации.
- `am task resize` может быть запрещён shell UID или изменён производителем прошивки.
- Некоторые приложения игнорируют Freeform, закрывают окно, перезапускают Activity или имеют минимальную ширину.
- Rutube и его Activity в текущей конфигурации не подтверждены.
- Интеграция Shizuku UserService требует проверки компиляцией и фактическим запуском.

Если GitHub Actions завершится ошибкой, открой failed job, скопируй полный лог ошибки и пришли его сюда. По нему можно будет исправить именно проблему сборки, не трогая магнитолу.

## Проверка на магнитоле после получения APK

1. Установить `app-debug.apk`.
2. Запустить Shizuku и убедиться, что служба имеет статус Running.
3. Открыть GS8 Triple, подключить Shizuku и выдать разрешение.
4. Назначить приложения для левого, центрального и правого слотов.
5. Проверить доступ и Freeform.
6. Нажать «Разложить три окна».
7. Если окна не встали на места, прислать полный журнал диагностики.
